# v6 前端展示版規劃

## 目標

v6 先整理未來前端展示版的方向，讓目前的 Streamlit 工具可以自然延伸成更漂亮、也更接近正式產品的前端作品。

目前 Streamlit 版本負責驗證資料流程、家庭共用邏輯與 PostgreSQL 保存。前端展示版會以更完整的視覺介面呈現同一個產品概念，適合作為作品集主視覺。

## 建議技術

- Next.js 或 React
- TypeScript
- Tailwind CSS
- shadcn/ui 或 Radix UI
- lucide-react
- Recharts 或 Tremor

## 視覺方向

- 以家庭冰箱管理為主題，使用乾淨、明亮、容易掃描的介面。
- 不做過度花俏的 landing page，第一畫面直接是可操作的 Dashboard。
- 主色可使用清爽綠色或藍綠色，搭配中性色背景。
- 食材卡片要能快速看出狀態：已過期、今天到期、即將到期、安全。
- 手機版要保留核心操作：查看即期食材、新增食材、標記已使用。

## 主要頁面

### 1. Dashboard

- 顯示總食材數、今天到期、7 天內到期、已過期。
- 分區顯示已過期、今天到期與 7 天內到期食材。
- 顯示家庭名稱與目前登入成員。
- 支援快速進入新增食材。

### 2. 食材清單

- 食材卡片顯示名稱、分類、數量、到期日、剩餘天數、狀態。
- 支援狀態篩選、分類篩選與排序。
- 可標記已使用、編輯、刪除。
- 表格檢視可作為桌機版輔助模式。

### 3. 新增 / 編輯食材

- 使用同一組表單元件。
- 欄位包含名稱、分類、數量、購買日期、到期日期、備註。
- 到期日期不可早於購買日期。

### 4. 家庭管理

- 顯示家庭名稱、家庭代碼、邀請碼狀態。
- 顯示家庭成員與加入時間。
- 未來可加入管理員 / 一般成員角色。

### 5. 設定頁

- 顯示資料來源。
- 提供未來通知設定入口。
- 說明目前版本限制。

## 元件規劃

- `AppShell`：整體版面、側邊欄、手機版導覽。
- `StatCard`：Dashboard 統計卡片。
- `FoodCard`：食材資訊卡片。
- `StatusBadge`：期限狀態標籤。
- `FoodForm`：新增與編輯食材表單。
- `FilterToolbar`：篩選與排序工具列。
- `FamilySwitcher`：家庭與成員資訊區。
- `MemberList`：家庭成員列表。

## 開發順序

1. 建立 Next.js / React 前端專案骨架。（v7 已先使用 React / Vite 完成展示版）
2. 先使用 mock data 完成畫面。（v7 已完成）
3. 補 Dashboard 與食材清單互動。（v7 已完成基礎互動）
4. 接上 FastAPI 或 Streamlit 後端整理出的 API。（v9 已完成 FastAPI 基礎串接）
5. 加入登入與家庭權限。
6. 整理 README、截圖與 Demo 連結。

## 暫不處理

- LINE 通知。
- OCR 辨識。
- AI 食譜推薦。
- 付費或正式商用權限系統。
